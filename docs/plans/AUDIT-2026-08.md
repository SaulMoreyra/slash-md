## Bloqueadores

### B1 — Árbol sucio

Ver arriba. **Estado:** pendiente del usuario.

### B2 — El plan 01 no eliminaba el segundo clic

**Hallazgo.** `useRun` usa `busyRef` síncrono, así que el IPC duplicado ya estaba bloqueado. El síntoma real es que el **primer** clic se descarta en silencio cuando hay algo en vuelo (`run` devuelve `undefined`). La propuesta original —toast + rechazo— explicaba el problema pero dejaba intacta la necesidad del segundo clic.

**Corrección aplicada.** El plan 01 pasó a estrategia de **cola**: las acciones del usuario se encolan y se ejecutan al liberarse el lock, con deduplicación por operación. El refresh de fondo sí se descarta.

**Estado:** aplicado.

## Correcciones factuales

### C1 — Toast de HeroUI: disponible

`dist/index.d.ts` solo tiene cuatro líneas de `export *`, pero `dist/components/index.d.ts` línea 39 hace `export * from "./toast"`. O sea, `import { Toast, toast } from "@heroui/react"` funciona.

API real: `Toast.Provider`, `toast()`, `toast.info/success/warning/danger()`, `toast.promise()`, `toast.close()`, `toast.clear()`.

**Estado:** aplicado al plan 01 con la API textual.

### C2 — `electron-store` no instalado y ESM-only

No está en `node_modules`. Las versiones actuales son ESM-only: el main es ESM, pero el preload se compila a **CJS** (`vite.config.ts`: `formats: ["cjs"]`). Además `electron/` hoy no tiene ninguna dependencia de runtime.

**Corrección aplicada.** Plan 00 cambió a un JSON propio en `app.getPath("userData")`, unas 20 líneas con `node:fs`, sin dependencia nueva.

**Estado:** aplicado.

### C3 — `window.__SLASHMD_INITIAL_THEME__` necesita el bridge

Con `contextIsolation: true`, asignar `window.x` desde el preload no lo hace visible al script de la página. Hay que usar `contextBridge.exposeInMainWorld`.

**Estado:** aplicado al plan 00.

### C4 — El script inline no puede tocar `document.body`

Está en `<head>`, donde `<body>` todavía no existe. La versión original usaba `DOMContentLoaded`, lo que reabre el gap que queríamos cerrar.

**Corrección aplicada.** El script solo toca `<html>`; los selectores CSS pasan a `html.dark body` / `html.light body`.

**Estado:** aplicado al plan 00.

### C5 — `styles.css` es tan crítico como `index.html`

Confirmado en la línea 101: `body, body.vscode-dark, body.vscode-high-contrast { color-scheme: dark; … }`. Un `body` sin clase es oscuro, incluyendo todos los tokens del editor Milkdown. Poner `class="light"` en `<html>` no basta.

**Estado:** aplicado al plan 00 como cambio obligatorio, no opcional.

### C6 — `useRun` no es solo para git

La misma instancia la usa `usePageSession` (`savePage`, `openPage`). Un toast que diga "operación git en curso" mentiría cuando lo que bloquea es un guardado.

**Corrección aplicada.** El enum pasó de `GitOperation` a `AppOperation`, con clasificación `background` vs `userAction`.

**Estado:** aplicado al plan 01.

### C7 — Ventana de doble disparo en `useHomeActions`

```ts
await run(() => api().publishBatch(publicationPr));
await onRefresh();   // el lock ya se liberó aquí
```

`run` libera `busyRef` en su `finally`, antes del refresh. Durante ese refresh el botón vuelve a estar habilitado. Mismo patrón en `onSignOut`, `onLeavePublication`, `onInitWorkspace`, `onSaveConfig`, `onSignIn`, `onSendReview`.

**Corrección aplicada.** El plan 01 exige que el refresh vaya **dentro** del mismo `runOp`.

**Estado:** aplicado.
